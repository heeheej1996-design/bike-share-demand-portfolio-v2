**목표: 2015년 데이터로 회귀 모델을 학습해 2016년 일일 대여량(`cnt`)을 예측한다.**

|---|---|---|---|
| **Train** | `data/london_daily_2015.csv` | 362일 × 17열 | 2015-01-04 ~ 2015-12-31 |

### 이 워크플로우에서 가져올 원칙

1. **번호가 곧 실행 순서** — 산출물 파일명 앞 번호 = 만든 스크립트 번호
2. **분할 조건 고정** — `random_state=42`, 모든 스크립트에서 동일
3. **타겟 누수 차단** — 타겟을 구성하는 변수는 피처에서 제외
4. **이상 신호는 추가 실험으로 검증** — 그냥 보고하지 않음 (`yr` ablation)
5. **숫자를 지어내지 않음** — 실행 출력으로 확인한 값만 문서에 기재
6. **한계를 별도 절로 명시** — 성능 수치만 남기지 않음

## 2부. 런던에 그대로 적용하면 안 되는 것

계획 수립 중 데이터에서 확인한 문제입니다. **둘 다 성능을 망가뜨립니다.**

### ⚠️ 문제 1 — `yr`은 반드시 제외해야 합니다

```
train(2015) yr 고유값: [0]   ← 상수
test (2016) yr 고유값: [1]   ← 학습에서 본 적 없는 값
```

연도로 파일을 나눴으니 당연한 결과입니다. 하지만 결과는 치명적입니다.

- 학습 데이터에서 `yr`은 **항상 0** → 모델이 이 변수에서 배울 게 없습니다
- 예측 시점에는 **항상 1** → 트리 모델은 학습 때 못 본 분기를 만나 전부 한쪽으로 흘려보냅니다

워싱턴에서는 `yr`이 전체 중요도의 47%를 차지한 1위 변수였습니다. 그 코드를 그대로 복사하면 **가장 중요한 변수 자리에 아무 정보도 없는 상수가 들어갑니다.**

→ **`yr`을 피처에서 제외합니다.** 워싱턴 REPORT의 결론("`yr`을 연속 트렌드 변수로 재설계해야 한다")이 런던에서 현실이 된 경우입니다.

부작용도 알고 가야 합니다. 런던은 2015→2016 성장이 **+3.2%**에 그쳐(워싱턴은 +64%) 연도 변수의 손실이 작습니다. 이건 다행인 부분입니다.

### ⚠️ 문제 2 — 2015년에 설명 불가능한 극단값 2일이 있습니다

```
2015-07-09   cnt 72,504   ← 중앙값의 2.7배
2015-08-06   cnt 63,468   ← 중앙값의 2.4배
```

IQR 기준 상한이 48,577인데 이를 크게 넘습니다. 두 날 모두 **날씨 좋음·평일·24시간 온전 기록**이라 데이터 품질 문제가 아닙니다. 즉 날씨 변수로는 설명할 수 없는 값입니다.

비교하면 2016년 최대값은 46,021로, **2015년 최대값(72,504)의 63%에 불과**합니다. 즉 학습 데이터에만 있는 극단값입니다.

**유력한 가설: 런던 지하철 파업.** 2015년 7월 9일과 8월 6일에 튜브 파업이 있었던 것으로 알려져 있습니다. 파업일에는 자전거 대여가 폭증합니다. **다만 이 계획서 작성 시점에 외부 자료로 확인하지 않았으므로, 검증 전까지는 가설로만 둡니다.**

→ 이 2일을 어떻게 다루느냐가 성능에 직접 영향을 줍니다. `05_outlier_detection.py`에서 정면으로 다룹니다.

### 그 밖에 확인한 것

| 항목 | 확인 결과 | 조치 |
|---|---|---|
| 분포 이동 | `cnt` +3.2%, `t1` −1.8%, `wind_speed` −8.8% | 경미. 별도 보정 불필요 |
| `weather_code` 미지값 | test에 `9`,`10`이 있으나 train에 없음 (train엔 `8`이 있으나 test에 없음) | 트리 모델은 수치 분기라 동작. **범주형 인코딩 시에는 문제** |
| `season` 분포 | train/test 거의 동일 (각 계절 87~92일) | 조치 불필요 |
| 결측 | `coverage < 0.90`이 2015년 7일, 2016년 5일 | 학습에서 제외 검토 |
| 2015년 일수 | 362일 (1/1~1/3 없음) | 원본 수집 시작일 문제. 정상 |

DROP = ["instant", "dteday", "cnt",      # 식별자·날짜·타겟

#### 05 — 이상치 탐지

**세 가지 방법을 모두 계산해 대조합니다.** 하나만 쓰면 놓칩니다.

| 방법 | 기준 | 목적 |
|---|---|---|
| IQR | `Q1 - 1.5×IQR` ~ `Q3 + 1.5×IQR` | 분포 기반 |
| z-score | \|z\| > 3 | 정규성 가정 기반 |
| **모델 잔차** | 선형회귀 잔차 \|z\| > 3 | **"날씨로 설명되지 않는 날"** |

세 번째가 핵심입니다. 2015-07-09는 날씨가 좋아서 IQR로도 잡히지만, 잔차 기준으로 보면 **"이 날씨면 3만 건이어야 하는데 7만 건"** 이라는 게 드러납니다.

**처리 방침 — 세 가지를 모두 실험하고 2016 성능으로 판정합니다.**

| 방침 | 근거 |
|---|---|
| (A) 그대로 둠 | 실제 발생한 수요. 제거하면 정보 손실 |
| (B) 제거 | 설명 변수가 없는 날을 학습하면 모델이 왜곡됨 |
| (C) 상한 클리핑 (winsorize) | 절충안 |

**주의: 이상치 판단은 2015년에서만 합니다.** 2016년을 보고 결정하면 테스트 정보 유입입니다. 2016년 이상치는 "예측 실패 사례"로 `12`에서 다룹니다.

`coverage < 0.90`인 7일도 여기서 함께 검토합니다 — 기록이 부실해 `cnt`가 실제보다 낮은 날입니다.

#### 06 — 베이스라인

**워싱턴에 없던 단계입니다.** 나이브 기준선 없이 R²만 보면 모델이 잘한 건지 알 수 없습니다.

| 기준선 | 예측값 | 의미 |
|---|---|---|
| 전체 평균 | 2015년 `cnt` 평균 | R² = 0 지점 |
| 월별 평균 | 그 달의 2015년 평균 | 계절성만 반영 |
| 요일×월 평균 | 해당 조합의 평균 | 달력 정보만 반영 |

여기에 선형회귀를 더해 4종을 비교합니다. **모델이 "요일×월 평균"을 못 이기면 날씨 변수가 값을 못 하고 있다는 뜻입니다.**

#### 07 — 모델 비교

워싱턴과 동일하게 LinearRegression / RandomForest / XGBoost를 비교하되, **평가 방식이 다릅니다.**

- 워싱턴: 전체를 8:2 랜덤 분할
- **런던: 2015 전체로 학습 → 2016 전체로 평가**

이 시점에서 2016 성능을 보게 되는데, 이후 `09` 튜닝에서 이 정보를 쓰면 누수입니다. **`07`의 2016 성능은 참고용으로만 기록하고, 모델 선택은 `08`의 CV 결과로 합니다.**

지표는 R², RMSE, MAE 3종. 워싱턴과 동일합니다.

#### 08 — 교차검증 (2015 내부)

**`KFold(shuffle=True)`를 쓰면 안 됩니다.** 시계열이라 랜덤 셔플은 미래 정보를 학습에 넣습니다. 워싱턴이 남긴 한계가 바로 이것입니다.

```python
from sklearn.model_selection import TimeSeriesSplit
tscv = TimeSeriesSplit(n_splits=5)   # 2015년 362일을 시간순으로 5분할
```

다만 `TimeSeriesSplit`은 첫 fold의 학습 데이터가 매우 짧습니다(약 60일). 겨울만 학습해 봄을 예측하는 셈이라 점수가 낮게 나옵니다. **`KFold`와 `TimeSeriesSplit` 결과를 나란히 출력해 차이를 기록하고, 모델 선택은 `TimeSeriesSplit` 기준으로 합니다.**

#### 09 — 튜닝

**2015년만 사용합니다.** 워싱턴은 전체 데이터에 `GridSearchCV`를 돌려 테스트 정보가 유입됐고, 스스로 한계로 기록했습니다. 런던에서는 이를 고칩니다.

`08`에서 가장 좋았던 모델을 대상으로 `GridSearchCV(cv=TimeSeriesSplit(5))`를 수행합니다. 탐색 범위는 워싱턴 `08`의 그리드(144조합)를 출발점으로 하되, 2015년이 362일로 워싱턴(731일)의 절반이라 **과적합 방지 쪽으로 범위를 조정**합니다(`max_depth` 상한을 낮추고 `min_child_weight` 추가 검토).

#### 11 — 변수 중요도

- 최종 모델의 `feature_importances_` 순위·차트
- **ablation 실험** — 상위 변수를 뺐을 때 성능 변화

워싱턴은 `yr` ablation을 했지만 런던에는 `yr`이 없습니다. 대신 **`t1`(기온)과 `weather_code`** 를 대상으로 합니다. 특히 `weather_code`는 2부에서 본 대로 **56일이 존재하지 않는 코드값**이라, 이 변수가 실제로 기여하는지 확인할 필요가 있습니다.

#### 12 — 오차 분석

**워싱턴에 없던 단계이며, 이 프로젝트에서 가장 실질적인 부분입니다.**

- 2016년 365일 중 **가장 크게 틀린 20일**을 뽑아 원인 분류
- 잔차를 월별·계절별·요일별·날씨별로 집계 → 특정 구간에서 체계적으로 편향되는지
- 과대예측 / 과소예측 경향 확인
- 2015년 이상치 처리 방침(A/B/C)별로 2016 성능이 어떻게 달라졌는지 정리

#### REPORT.md

워싱턴 `REPORT.md`의 8절 구성을 따릅니다: 데이터 확인 → EDA → 베이스라인 → 모델 비교 → 검증 → 튜닝 → 해석 → 결론. 여기에 **이상치 탐지 절과 오차 분석 절**을 추가합니다.

한계 절에 반드시 포함할 것:
- `yr` 제외 결정과 그 이유
- 이상치 2일의 원인이 **미확인 가설**이라는 점
- `weather_code`의 구조적 문제
- 1년치(362일)만으로 학습했다는 표본 한계

### 워싱턴보다 낮게 나오는 것이 정상입니다

| | 워싱턴 | 런던 |
|---|---|---|
| 분할 | 랜덤 8:2 (인접일이 학습셋에 있음) | **완전 시간 분리** |

| 최강 변수 | `yr` (중요도 47%) | **사용 불가** |
| 보고된 R² | 0.904 | ? |

워싱턴 0.904는 **낙관적으로 부풀려진 수치**라고 스스로 기록해 두었습니다. 런던이 이보다 낮게 나오면 모델이 나빠서가 아니라 **평가가 정직해졌기 때문**입니다. 두 숫자를 직접 비교하면 안 되며, REPORT에 이 점을 명시합니다.

| 위험 | 영향 | 대응 |
