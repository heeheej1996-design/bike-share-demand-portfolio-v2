# 분석 리포트: 자전거 대여 수요 예측

이 문서는 `scripts/01`~`12`를 실행한 실제 결과를 바탕으로 분석 과정을 서술합니다. 모든 수치는 `data/day.csv`를 입력으로 각 스크립트를 직접 실행해 나온 값이며, 재현 방법은 [`README.md`](README.md)를 참고하세요.

## 1. 데이터 확인 (`01_explore_data.py`)

- 731행 x 16열, 기간 2011-01-01 ~ 2012-12-31.
- 컬럼 타입: `int64` 11개, `float64` 4개(`temp`, `atemp`, `hum`, `windspeed`), `object` 1개(`dteday`).
- **결측치: 전체 16개 컬럼 모두 0개.** 별도의 결측치 처리·이상치 제거 등 정제 작업이 필요하지 않음을 확인하고 원본 그대로 사용했습니다.
- `casual`(비회원) + `registered`(회원) = `cnt`(전체 대여 건수) 관계를 확인했고, 이후 모델링에서 `casual`/`registered`를 입력 변수로 쓰면 타겟을 그대로 알려주는 셈(타겟 누수)이라 제외했습니다.

## 2. 탐색적 분석 및 시각화 (`02`, `03`)

**기온 vs 대여 건수** (`02_plot_temp_vs_cnt.py`)
`temp`는 `(t - t_min) / (t_max - t_min)`로 정규화된 값(`t_min=-8°C`, `t_max=39°C`)이라 실제 섭씨로 역변환해 산점도를 그렸습니다. Pearson 상관계수 **r = 0.63**으로 중간~강한 양의 상관관계를 보이며, 25~30°C 부근에서 대여량이 정점을 찍고 그 이상에서는 소폭 꺾이는 비선형적 패턴이 관찰됩니다.

**날씨/계절/요일 패턴** (`03_plot_weather_season_weekday.py`)

| 날씨 등급 | 일수 | 평균 대여 건수 |
|---|---|---|
| 맑음 | 463일 | 4,877건 |
| 흐림/안개 | 247일 | 4,036건 |
| 악천후(비/눈) | 21일 | 1,803건 |

날씨가 나쁠수록 대여량이 뚜렷하게 감소합니다. (참고: `weathersit`는 1~3만 관측되며, 가장 심한 4등급에 해당하는 날은 원본 데이터에 없습니다.)

계절 x 요일 평균 대여 건수 히트맵에서는 봄이 전 요일에 걸쳐 가장 낮고(일요일 2,229건이 전체 최저), 가을이 가장 높습니다(수요일 5,854건이 전체 최고). 여름·겨울은 주 후반(금·토)으로 갈수록 소폭 상승하는 경향을 보입니다.

## 3. 베이스라인: 선형회귀 (`04_linear_regression_cnt.py`)

- 입력 변수 11개: `season`, `yr`, `mnth`, `holiday`, `weekday`, `workingday`, `weathersit`, `temp`, `atemp`, `hum`, `windspeed` (`instant`/`dteday`/`casual`/`registered`/`cnt` 제외)
- 8:2 분할(학습 584건 / 테스트 147건, `random_state=42`)
- **테스트셋 성능: R² 0.8277, RMSE 831.29, MAE 617.39**
- 회귀 계수(영향력 순): `atemp` +3488, `temp` +2097, `windspeed` −2081, `yr` +2024, `hum` −865, `weathersit` −633, `season` +525, `holiday` −392, `workingday` +161, `weekday` +73, `mnth` −38
- 온도가 오를수록, 바람이 약할수록, 날씨가 좋을수록, 2012년(`yr=1`)일수록 대여량이 늘어나는 방향과 일치합니다.

## 4. 트리 모델과의 비교 (`05`, `06`)

동일한 8:2 분할로 LinearRegression, RandomForest(`n_estimators=300`), XGBoost(`n_estimators=300, max_depth=4, learning_rate=0.05`)를 비교했습니다.

| 모델 | R² | RMSE | MAE |
|---|---|---|---|
| LinearRegression | 0.8277 | 831.29 | 617.39 |
| RandomForest | 0.8867 | 674.17 | **426.20** |
| XGBoost | **0.8928** | **655.49** | 446.11 |

트리 모델이 선형회귀보다 뚜렷하게 우수했습니다. 다만 지표별 승자가 갈리는 점도 확인됩니다 — R²·RMSE는 XGBoost가, MAE는 RandomForest가 근소하게 더 좋습니다. `06_plot_model_comparison.py`는 이 비교를 기준 대비 델타값과 지표별 최고 모델(★) 표시로 시각화합니다.

## 5. 교차검증으로 재확인 (`07_cross_validate_models.py`)

단일 분할 결과가 우연이 아닌지 5-fold `KFold(shuffle=True, random_state=42)` 교차검증으로 재확인했습니다.

| 모델 | 5-fold R² 평균 ± 표준편차 |
|---|---|
| LinearRegression | 0.7832 ± 0.0416 |
| RandomForest | 0.8747 ± 0.0263 |
| XGBoost | 0.8818 ± 0.0258 |

단일 분할과 동일한 순위가 재현되어, **트리 모델이 선형회귀보다 우수하다는 점**이 특정 분할에서만 나타난 우연이 아님을 확인했습니다(격차 약 0.09로, 각 모델의 표준편차보다 훨씬 큽니다).

다만 RandomForest와 XGBoost 사이의 차이(0.8747 vs 0.8818, 0.0071)는 **두 모델의 표준편차(±0.026)보다 작아 통계적으로 유의미하다고 보기 어렵습니다.** 단일 분할에서도 R²·RMSE는 XGBoost가, MAE는 RandomForest가 더 좋았던 것과 일관됩니다 — 이 데이터에서 두 트리 모델은 사실상 동등한 성능으로 보는 것이 타당하며, 이후 XGBoost를 튜닝 대상으로 택한 것은 "더 우수해서"가 아니라 하이퍼파라미터 탐색 비용이 낮기 때문입니다.

트리 모델이 선형회귀보다 우수한 이유로는 (1) 기온-대여량 관계의 비선형성(30°C 부근에서 꺾임), (2) 날씨·계절·근무일 등 변수 간 상호작용을 트리가 더 잘 포착, (3) `temp`-`atemp` 다중공선성이 선형모델 계수를 불안정하게 만드는 점을 꼽을 수 있습니다.

## 6. XGBoost 하이퍼파라미터 튜닝 (`08_tune_xgboost.py`)

`GridSearchCV`로 5개 파라미터를 완전 탐색했습니다.

| 파라미터 | 후보값 |
|---|---|
| `n_estimators` | 100, 300, 500 |
| `max_depth` | 3, 4, 5, 6 |
| `learning_rate` | 0.01, 0.05, 0.1 |
| `subsample` | 0.8, 1.0 |
| `colsample_bytree` | 0.8, 1.0 |

3×4×3×2×2 = **144개 조합**을 `07`과 동일한 5-fold CV(`scoring="r2"`)로 전부 평가했습니다.

**최적 조합**: `n_estimators=300, max_depth=4, learning_rate=0.05, subsample=0.8, colsample_bytree=0.8`

| | 튜닝 전 | 튜닝 후 |
|---|---|---|
| 5-fold CV R² | 0.8818 | 0.8967 |
| 테스트셋 R² | 0.8928 | **0.9040** |
| 테스트셋 RMSE | 655.49 | **620.45** |
| 테스트셋 MAE | 446.11 | **410.13** |

기본값 대비 실제로 바뀐 값은 `subsample`·`colsample_bytree`(1.0→0.8)뿐이었습니다. 매 트리가 데이터의 80%만 무작위로 사용하도록 해 트리 간 다양성을 높이고 과적합을 줄인 것이 R²/RMSE/MAE 전 지표의 일관된 개선(MAE 기준 −8.1%)으로 이어졌습니다. 최종 모델은 `09_save_final_model.py`가 이 하이퍼파라미터로 동일 8:2 분할에 재학습해 `output/09_final_xgboost_model.joblib`로 저장합니다.

## 7. 결과 해석: 변수 중요도와 `yr`의 정체 (`11`, `12`)

최종 모델의 변수 중요도(`11_feature_importance.py`):

| 순위 | 변수 | 중요도 |
|---|---|---|
| 1 | `yr` | 0.4749 |
| 2 | `temp` | 0.1042 |
| 3 | `season` | 0.1020 |
| 4 | `atemp` | 0.0995 |
| 5 | `weathersit` | 0.0645 |
| 6 | `mnth` | 0.0617 |
| 7 | `hum` | 0.0296 |
| 8 | `windspeed` | 0.0172 |
| 9 | `holiday` | 0.0167 |
| 10 | `weekday` | 0.0165 |
| 11 | `workingday` | 0.0134 |

날씨/계절 변수들이 상식과 맞게 상위권에 분포하는 것과 달리, `yr`(단순히 2011년인지 2012년인지)이 전체 중요도의 절반 가까이(47%)를 차지하는 건 직관적이지 않습니다. 이게 실제로 중요한 신호인지, 아니면 모델이 과도하게 의존하는 것인지 확인하기 위해 `12_without_yr_comparison.py`에서 `yr`을 뺀 채 동일한 하이퍼파라미터·분할로 재학습하는 ablation(변수 제거) 실험을 했습니다.

| | R² | RMSE | MAE |
|---|---|---|---|
| `yr` 포함 | 0.9040 | 620.45 | 410.13 |
| `yr` 제외 | 0.6010 | 1264.89 (+103.9%) | 1048.59 (+155.7%) |

성능이 절반 수준으로 떨어져, `yr`이 실제로 핵심적인 예측 신호임을 확인했습니다. 원인을 데이터에서 직접 확인해보면: `yr=0`(2011년) 일평균 대여 3,405.76건 → `yr=1`(2012년) 일평균 5,599.93건으로 **약 64% 증가**했습니다. 이 기간 Capital Bikeshare 서비스 자체가 급성장했고, `yr`은 날씨와 무관하게 "그 해의 서비스 규모/기준선"을 통째로 갈라주는 변수였던 것입니다. 트리 모델은 평균이 거의 2배 차이 나는 두 그룹으로 데이터를 나눌 수 있는 분할을 선호하기 때문에 `yr`의 중요도가 두드러지게 높게 잡혔습니다. 실제로 `yr`을 제외하면 1위가 `temp`(0.234)로 바뀌며 날씨 변수들의 비중이 커집니다 — `yr`이 있을 때는 이 신호들이 상대적으로 눌려 있었던 셈입니다.

## 8. 결론

- 731일 규모의 정형 데이터에서는 트리 기반 모델(RandomForest, XGBoost)이 선형회귀 대비 뚜렷한 성능 우위를 보였고, 5-fold 교차검증으로 이 우위가 특정 분할의 우연이 아님을 확인했습니다.
- GridSearchCV 기반 체계적 튜닝으로 XGBoost 테스트셋 R²를 0.8928 → 0.9040으로, MAE를 8.1% 개선했습니다.
- 최종 모델에서 가장 중요한 변수는 날씨가 아니라 `yr`(연도)이었고, ablation 실험과 실제 그룹 평균 비교로 이 원인이 "서비스 성장 트렌드"임을 정량적으로 검증했습니다.
- **한계**: `yr`이 이진 변수(0/1)라는 점은 이 모델이 관측되지 않은 미래 연도(2013년 이후)로 일반화되기 어렵다는 뜻이기도 합니다. 실제 서비스에 적용한다면 `yr`을 시간 흐름에 따라 연속적으로 커지는 트렌드/카운터 변수로 바꾸는 재설계가 필요합니다.
