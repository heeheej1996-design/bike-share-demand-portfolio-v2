# 시간별 → 일별 변환 규칙서

시간 단위로 기록된 대여 데이터를 날짜 단위로 집계할 때 적용하는 규칙입니다. 워싱턴 D.C. 데이터(`01-washington/data/`)에서 `bike_sharing_hour.csv`(17,379행)와 `day.csv`(731행)를 731일 전수 대조해 **역으로 추출한 규칙**이며, 다른 도시 데이터(런던 등)에도 동일하게 적용하는 것을 전제로 작성했습니다.

추측이 아니라 후보 집계 방식을 전부 계산해 원본과 맞춰본 결과입니다. 검증 과정은 [부록 A](#부록-a-규칙을-어떻게-확정했는지)에 있습니다.

## 1. 컬럼 종류별 규칙

컬럼을 성격에 따라 네 종류로 나누고, 종류마다 다른 규칙을 적용합니다.

| 종류 | 규칙 | 워싱턴 데이터의 해당 컬럼 |
|---|---|---|
| **누적량** (flow) | **합계** `sum` | `casual`, `registered`, `cnt` |
| **연속 상태량** (level) | **평균** `mean` | `temp`, `atemp`, `hum`, `windspeed` |
| **순서형 상태량** (ordinal) | **평균 후 반올림** (half-up) | `weathersit` |
| **날짜 속성** (calendar) | **그날의 값 그대로** (`first`) | `season`, `yr`, `mnth`, `holiday`, `weekday`, `workingday` |
| **행 식별자** | **재생성** (1부터 날짜순) | `instant` |

### 판단 기준

새로운 컬럼을 만났을 때 어느 종류인지 정하는 기준입니다.

- **누적량인가?** — "그 시간 동안 몇 건 발생했나"를 세는 값이면 합계입니다. 대여 건수, 반납 건수, 강수량(mm) 등. 하루치는 24시간을 더한 값이어야 의미가 맞습니다.
- **상태량인가?** — "그 시점에 얼마였나"를 재는 값이면 평균입니다. 기온, 습도, 풍속, 체감온도. 이런 값은 더하면 의미가 없습니다(기온 24개를 더한 값은 아무 의미도 없음).
- **순서형인가?** — 상태량인데 정수 코드로 표현된 값(날씨 등급 1·2·3·4)이면 평균을 낸 뒤 반올림합니다. 자세한 주의사항은 [2절](#2-반올림-주의사항).
- **날짜 속성인가?** — 하루 안에서 절대 변하지 않는 값(요일, 월, 공휴일 여부)이면 집계가 아니라 그대로 가져옵니다. 단, **가져오기 전에 정말 상수인지 검사해야 합니다.** [3절](#3-날짜-속성-컬럼-검사) 참고.

### 애매한 경우

- **최대/최소가 더 맞는 컬럼** — "그날 최고기온"처럼 애초에 극값을 원하는 파생 변수라면 `max`/`min`을 씁니다. 다만 이건 원본 재현이 아니라 **새 피처를 만드는 것**이므로 컬럼명을 `temp_max`처럼 구분해서 붙이고, 원본 `temp`(평균)와 함께 두세요.
- **비율/백분율 컬럼** — 평균으로 집계하면 시간별 가중치가 무시됩니다. 가능하면 분자·분모를 각각 합계로 집계한 뒤 일별 단계에서 나누세요.

## 2. 반올림 주의사항

### half-up과 half-even은 결과가 다릅니다

`weathersit`은 시간별 평균을 낸 뒤 반올림하는데, **반올림 방식이 half-up(사사오입)** 입니다. 파이썬 내장 `round()`와 `numpy.round()`, `pandas.Series.round()`는 모두 **half-even(은행가 반올림)** 이라 결과가 어긋납니다.

| 평균 | half-up | half-even | 원본 day.csv |
|---|---|---|---|
| 1.5 | 2 | 2 (짝수로) | 2 |
| **2.5** | **3** | **2 (짝수로)** | **3** |
| 3.5 | 4 | 4 (짝수로) | 4 |

워싱턴 데이터에서 평균이 정확히 `.5`로 떨어지는 날은 25일이고, 그중 **두 방식이 갈리는 날은 2일**입니다.

- `2011-04-16` — weathersit `2`가 12시간, `3`이 12시간 → 평균 정확히 2.5 → 원본 값 **3**
- `2012-02-11` — `1`이 1시간, `2`가 10시간, `3`이 13시간 (합계 60) → 평균 정확히 2.5 → 원본 값 **3**

나머지 23일은 평균이 1.5인데, 이 경우 half-even도 짝수인 2로 올라가 우연히 일치합니다. 그래서 `round()`를 쓰면 **729/731만 맞고 2일이 틀립니다.** 전수 대조를 하지 않으면 놓치기 쉬운 차이입니다.

### 올바른 구현

```python
import numpy as np

def half_up(s):
    """사사오입 반올림. np.round / pandas .round() 는 half-even 이라 쓰면 안 됨."""
    return np.floor(s + 0.5).astype(int)
```

음수가 들어올 수 있는 컬럼에 쓸 때는 `np.sign(s) * np.floor(np.abs(s) + 0.5)` 형태로 바꿔야 합니다. 위 데이터의 `weathersit`은 1~4라 문제되지 않습니다.

### 평균 컬럼의 소수점

`temp`, `atemp`, `hum`, `windspeed`는 원본 day.csv가 **소수점 6자리로 반올림 저장**되어 있습니다. 재현 결과를 비교할 때 `==`로 하면 부동소수점 오차 때문에 실패하므로 **허용오차 `1e-6`** 으로 비교하세요.

```python
np.isclose(생성값, 원본값, atol=1e-6)   # 731/731 일치
np.isclose(생성값, 원본값, atol=1e-9)   # 116~222일만 일치 (저장 정밀도 한계)
```

## 3. 날짜 속성 컬럼 검사

`season`, `yr`, `mnth`, `holiday`, `weekday`, `workingday`는 워싱턴 데이터에서 **하루 안에 값이 2개 이상인 날이 0일**이었습니다. 그래서 `first`, `mean`, `max`, `min`, `mode` 중 무엇을 써도 731/731로 같은 결과가 나옵니다. 즉 이 컬럼들은 집계 방식을 데이터로 특정할 수 없고, 애초에 상수라 아무거나 써도 되는 상태입니다.

다른 데이터에 적용할 때는 **이 상수 가정이 성립하는지 먼저 확인해야 합니다.** 성립하지 않으면(예: 자정을 걸쳐 `mnth`가 바뀌는 타임존 처리, 공휴일 플래그가 시간대별로 다르게 붙은 경우) `first`가 조용히 틀린 값을 만듭니다.

```python
def check_constant(hourly, cols, date_col="dteday"):
    """하루 안에서 값이 여러 개인 날짜를 반환. 비어 있어야 정상."""
    n = hourly.groupby(date_col)[cols].nunique()
    return n[(n > 1).any(axis=1)]
```

위반 날짜가 나오면 `first`로 넘어가지 말고, 왜 변하는지 원인을 먼저 확인하세요.

## 4. 결측 시간 처리

### 결측은 반드시 존재한다고 가정하세요

워싱턴 데이터는 731일 × 24시간 = **17,544행이어야 하는데 실제는 17,379행**으로 165행이 비어 있습니다.

| 결측 시간 수 | 날짜 수 |
|---|---|
| 0시간 (완전) | 655일 |
| 1~2시간 | 68일 |
| 3~5시간 | 0일 |
| 6~11시간 | 4일 |
| 12~23시간 | 4일 |
| **합계** | **731일** |

가장 심한 날은 다음과 같습니다.

| 날짜 | 결측 | 빠진 구간 | 배경(추정) |
|---|---|---|---|
| 2012-10-29 | 23시간 | 1시~23시 (0시만 존재) | 허리케인 샌디 |
| 2011-01-27 | 16시간 | 0시~15시 | 1월 폭설 |
| 2012-10-30 | 13시간 | 0시~12시 | 허리케인 샌디 여파 |
| 2011-01-18 | 12시간 | 0시~11시 | 1월 폭설 |
| 2011-08-28 | 8시간 | 0시~6시 | 허리케인 아이린 |

빠진 시간대가 **모두 연속 구간이고 대부분 하루의 앞부분**입니다. 랜덤 결측이 아니라 **서비스 중단 구간**입니다.

### 원본 규칙: 있는 시간만으로 계산

원본 day.csv는 **결측을 0으로 채우지 않고, 존재하는 시간만으로** 합계와 평균을 냅니다. 이 방식이 731일 전부 일치했습니다. 즉 `groupby().sum()` / `groupby().mean()`을 그냥 쓰면 됩니다 — 24로 나누는 게 아니라 실제 행 수로 나눕니다.

### 하지만 그 결과를 그대로 믿으면 안 됩니다

두 가지가 서로 다른 방향으로 위험합니다.

**합계 컬럼(`cnt` 등)** — 서비스가 멈춰 행이 없는 것이므로, 합계는 "수요가 적었다"가 아니라 **"측정하지 못했다"** 입니다. 2012-10-29의 `cnt=22`를 정상 수요로 학습하면 모델이 잘못된 패턴을 배웁니다. 0으로 채우는 것도 같은 문제이며, 오히려 "수요가 0이었다"는 더 강한 거짓 신호를 줍니다.

**평균 컬럼(`temp` 등)** — 남은 시간만의 평균이라 하루를 대표하지 못합니다. 2012-10-29의 일별 기온은 사실상 **0시 한 시점의 값**입니다.

### 권장 처리

1. **결측을 0으로 채우지 마세요.** 결측(NaN)과 0은 다릅니다.
2. **`coverage` 컬럼을 함께 만드세요.** 일별 데이터에 신뢰도 정보를 남기는 게 핵심입니다.
3. **임계값으로 필터링하거나 가중치로 쓰세요.** 워싱턴 데이터 기준 `coverage < 0.90`인 날은 8일, `< 0.75`는 6일, `< 0.50`은 3일입니다. 731일 중 몇 일 안 되므로 **제외해도 손실이 거의 없습니다.**

```python
g = hourly.groupby("dteday")
daily["n_hours"]  = g.size()
daily["coverage"] = g.size() / 24

# 학습에 쓸 때: 불완전한 날 제외
train = daily[daily["coverage"] >= 0.90]
```

`coverage`를 남겨두면 나중에 임계값을 바꿔가며 실험할 수 있고, 모델 성능이 이상할 때 결측 때문인지 바로 확인할 수 있습니다.

## 5. 참조 구현

아래 코드는 워싱턴 데이터에서 실제로 실행해 **16개 컬럼 전부 731/731 일치**를 확인한 것입니다. 컬럼 순서까지 원본 day.csv와 동일하게 나옵니다.

```python
import numpy as np
import pandas as pd

SUM_COLS   = ["casual", "registered", "cnt"]
MEAN_COLS  = ["temp", "atemp", "hum", "windspeed"]
ROUND_COLS = ["weathersit"]
CONST_COLS = ["season", "yr", "mnth", "holiday", "weekday", "workingday"]


def half_up(s):
    """사사오입. np.round / .round() 는 half-even 이라 쓰면 안 됨."""
    return np.floor(s + 0.5).astype(int)


def check_constant(hourly, date_col="dteday"):
    """날짜 속성 컬럼이 하루 안에서 상수인지 검사. 빈 결과여야 정상."""
    n = hourly.groupby(date_col)[CONST_COLS].nunique()
    return n[(n > 1).any(axis=1)]


def hourly_to_daily(hourly, date_col="dteday"):
    bad = check_constant(hourly, date_col)
    if len(bad):
        raise ValueError(f"날짜 속성이 상수가 아닌 날 {len(bad)}건:\n{bad}")

    g = hourly.groupby(date_col)
    daily = pd.concat([
        g[SUM_COLS].sum(),
        g[MEAN_COLS].mean(),
        g[ROUND_COLS].mean().apply(half_up),
        g[CONST_COLS].first(),
    ], axis=1).sort_index()

    # 결측 시간 정보 (원본 day.csv 에는 없지만 남겨두길 권장)
    daily["n_hours"]  = g.size()
    daily["coverage"] = g.size() / 24

    daily = daily.reset_index()
    daily.insert(0, "instant", np.arange(1, len(daily) + 1))
    return daily[["instant", date_col] + CONST_COLS + ROUND_COLS
                 + MEAN_COLS + SUM_COLS + ["n_hours", "coverage"]]
```

### 검증 방법

새 데이터에 적용할 때는 반드시 원본 일별 파일과 대조하세요. 규칙이 데이터마다 같다는 보장은 없습니다.

```python
def verify(generated, truth, mean_cols=MEAN_COLS):
    for c in truth.columns:
        if c in mean_cols:
            n = np.isclose(generated[c], truth[c], atol=1e-6).sum()
        else:
            n = (generated[c].values == truth[c].values).sum()
        mark = "OK" if n == len(truth) else "MISMATCH"
        print(f"{c:<12}{n:>6} / {len(truth)}  {mark}")
```

컬럼 하나라도 전체 일수를 채우지 못하면 그 컬럼의 집계 방식이 다른 것이므로, 부록 A의 방법으로 다시 판별하세요.

## 부록 A: 규칙을 어떻게 확정했는지

집계 방식을 짐작하지 않고 **후보를 전부 계산해 원본과 대조하는** 방식으로 찾았습니다. 같은 방법을 다른 데이터에도 쓸 수 있습니다.

**1단계 — 컬럼마다 7가지 후보를 계산해 일치 일수를 셉니다.** `sum`, `mean`, `max`, `min`, `mode`, `first`, `constant`. 결과(731일 중 일치 일수):

| 컬럼 | sum | mean | max | min | mode | first | 상수 |
|---|---|---|---|---|---|---|---|
| `casual` | **731** | 1 | 1 | 1 | 1 | 1 | 1 |
| `registered` | **731** | 1 | 1 | 1 | 1 | 1 | 1 |
| `cnt` | **731** | 1 | 1 | 1 | 1 | 1 | 1 |
| `temp` | 1 | **731** | 2 | 2 | 3 | 4 | 2 |
| `atemp` | 1 | **731** | 4 | 4 | 6 | 5 | 4 |
| `hum` | 2 | **731** | 2 | 2 | 3 | 3 | 2 |
| `windspeed` | 1 | **731** | 1 | 1 | 5 | 4 | 1 |
| `weathersit` | 1 | 163 | 226 | 480 | 629 | 490 | 154 |
| `season` 외 5개 | — | **731** | **731** | **731** | **731** | **731** | **731** |

**2단계 — 731을 채우는 후보가 없으면 후보를 넓힙니다.** `weathersit`이 여기 해당했습니다. 최빈값(629)이 가장 높았지만 정답이 아니었고, 반올림·중앙값·가중 최빈값까지 넓혀서야 답이 나왔습니다.

| 후보 | 일치 |
|---|---|
| **평균 → half-up 반올림** | **731 / 731** |
| 평균 → half-even 반올림 (`round`) | 729 / 731 |
| 중앙값 | 675 / 731 |
| 최빈값 (동점→큰 값) | 645 / 731 |
| 최빈값 (동점→작은 값) | 632 / 731 |
| 대여 수 가중 최빈값 | 623 / 731 |
| 하루 마지막 시간 값 | 493 / 731 |
| 하루 첫 시간 값 | 490 / 731 |

**3단계 — 여러 후보가 동시에 731이면 "특정 불가"로 기록합니다.** 날짜 속성 6개가 여기 해당했고, 원인은 하루 안에서 애초에 상수이기 때문이었습니다(3절).

**4단계 — 부분 일치를 무시하지 마세요.** 729/731은 "거의 맞음"이 아니라 **규칙이 틀렸다는 신호**입니다. 안 맞는 2일을 직접 열어보고 나서야 half-up이라는 걸 확정할 수 있었습니다.

## 부록 B: 컬럼 대응표

`day.csv`의 16개 컬럼은 `bike_sharing_hour.csv` 17개 컬럼의 **완전한 부분집합**이며, 차이는 `hr` 하나뿐입니다.

| 시간별 컬럼 | 일별 대응 | 집계 |
|---|---|---|
| `instant` | `instant` | 재생성 (의미가 다름 — 시간 일련번호 → 일 일련번호) |
| `dteday` | `dteday` | 그룹 키 |
| `hr` | *(없음)* | 집계로 소멸 |
| `season` `yr` `mnth` `holiday` `weekday` `workingday` | 동일 | `first` |
| `weathersit` | 동일 | `mean` → half-up |
| `temp` `atemp` `hum` `windspeed` | 동일 | `mean` |
| `casual` `registered` `cnt` | 동일 | `sum` |

`instant`는 이름이 같지만 **기준이 다릅니다.** 시간별은 1~17,379(시간 일련번호), 일별은 1~731(일 일련번호)입니다. 두 파일을 조인할 때 `instant`를 키로 쓰면 안 되고 `dteday`(+`hr`)를 써야 합니다.
