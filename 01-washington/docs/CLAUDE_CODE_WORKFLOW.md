# Claude Code로 이 분석을 수행한 과정

이 프로젝트는 터미널(CLI)에서 [Claude Code](https://claude.com/claude-code)와 대화하며 진행한 실제 작업 세션을 기반으로 합니다. 이 문서는 "AI가 대신 분석했다"는 이야기가 아니라, **사용자가 CLI 환경에서 Claude Code를 도구로 활용해 데이터 분석 워크플로우 전체를 어떻게 주도했는지**를 보여주기 위한 기록입니다.

## 1. 세션 재개: 상태를 스스로 확인시키기

작업은 여러 세션에 걸쳐 진행됐습니다. 새 세션을 시작할 때 "내가 마지막으로 작업한게 어디까지지?"라고만 물으면, Claude Code가 `worklogs/WORKLOG.md`와 `scripts/`, `output/`을 직접 읽어 진행 상황을 재구성하고 다음 단계를 제안했습니다. 즉 사람이 맥락을 다시 설명할 필요 없이, 프로젝트 자체(로그·코드·산출물)가 상태를 증명하는 방식으로 운영했습니다.

## 2. 파이프라인을 스크립트 단위로 분해하고 번호로 관리

`scripts/01_...`부터 `12_...`까지, 분석의 각 단계(데이터 확인 → EDA → 베이스라인 모델 → 트리 모델 비교 → 교차검증 → 튜닝 → 저장 → 해석)를 하나의 실행 가능한 스크립트로 분리하고 산출물 파일명을 스크립트 번호에 맞춰 관리했습니다. 이렇게 하면 "어느 단계에서 어떤 결론이 나왔는지"를 코드와 1:1로 추적할 수 있고, Claude Code가 이전 단계와 "동일한 분할(`random_state=42`)"을 유지하며 다음 스크립트를 작성하는 규칙을 스스로 지키게 만들 수 있었습니다.

## 3. 반복적 개선: 질문 → 실행 → 시각 확인 → 수정

단순히 코드를 한 번에 완성하지 않고, **결과를 실제로 렌더링해서 눈으로 확인한 뒤 문제를 고치는 루프**를 여러 번 거쳤습니다. 실제 사례:

- **모델 비교 차트 개선** — "가시성 있게 만들어줄 수 있어?"라는 요청에 대해, Y축을 0이 아닌 값에서 잘라 차이를 과장하는 대신(`dataviz` 스킬의 안티패턴 가이드 준수), 기준 대비 델타 주석과 지표별 최고 모델(★) 표시를 추가하는 방식을 택했습니다. 색상은 임의로 고르지 않고 `validate_palette.js` 검증 스크립트로 색각 이상(CVD) 대비를 통과하는지 실제로 실행해 확인했습니다.
- **표 이미지 렌더링 버그 수정** — 튜닝 전후 비교 표(`10`)를 처음 만들었을 때 헤더 텍스트("변화")가 오른쪽 끝에서 잘리는 걸 렌더링된 이미지를 직접 보고 발견했습니다. 원인(컬럼 중앙 정렬 오프셋 계산 오류)을 찾아 수정하고 다시 렌더링해 확인했습니다.
- **차트 레이아웃 버그 수정** — 변수 중요도 차트(`11`)에서 제목과 부제가 겹치는 문제를 이미지 확인 후 발견해, `ax.set_title`과 `fig.suptitle`을 분리하는 방식으로 재구성했습니다.

이 세 사례 모두 "코드가 실행됐다"에서 멈추지 않고 "실제 결과물을 확인해 문제를 찾고 고쳤다"는 점이 핵심입니다.

## 4. 숫자를 지어내지 않고 그때그때 계산해서 답하기

분석 중 나온 질문들 — "어느 모델이 가장 적합해?", "yr이 왜 중요해?", "yr 빼고 학습하면?" — 에 대해, 기억이나 짐작이 아니라 그 자리에서 스크립트를 실행하거나 `pandas`로 직접 집계해서 답했습니다. 예를 들어 "낯선 변수(`yr`)가 왜 중요한지" 설명할 때, `yr` 값별 `cnt` 평균(`groupby("yr")["cnt"].mean()`)을 실제로 계산해 "2011년 3,406건 → 2012년 5,600건(+64%)"이라는 근거를 확인한 뒤 설명에 사용했습니다. 이 포트폴리오 문서를 작성할 때도 마찬가지로, 모든 스크립트를 이 폴더 안에서 처음부터 다시 실행해 콘솔 출력을 직접 확인한 값만 README/REPORT에 옮겼습니다.

## 5. 결과 검증을 위한 추가 실험 설계

변수 중요도에서 `yr`이 47%로 압도적 1위로 나온 게 예상 밖이라는 점을 짚자, "그럼 진짜 중요한 게 맞는지" 검증하기 위해 `yr`을 제외하고 동일 조건으로 재학습하는 ablation 스크립트(`12_without_yr_comparison.py`)를 새로 설계해 실행했습니다. 이는 사전에 계획된 단계가 아니라, 분석 중 나온 질문에 답하기 위해 그때그때 실험을 추가한 사례입니다.

## 6. 문서화를 작업의 일부로

매 단계가 끝날 때마다 `worklogs/WORKLOG.md`에 무엇을 했고 어떤 수치가 나왔는지를 날짜와 함께 기록했습니다. 이 습관 덕분에 이 포트폴리오의 README/REPORT를 작성할 때도 과거 실행 결과를 신뢰할 수 있는 기록으로 다시 참조할 수 있었고, 최종적으로는 전체 파이프라인을 별도 폴더에서 재실행해 그 기록과 대조 검증하는 것으로 마무리했습니다.

## 요약: 이 워크플로우가 보여주는 것

| 능력 | 이 프로젝트에서의 예시 |
|---|---|
| 데이터 확인/정제 판단 | 결측치 0건을 확인하고, 불필요한 정제 없이 근거를 남긴 채 진행 |
| EDA → 시각화 | 상관관계, 분포, 히트맵을 목적에 맞는 차트 형태로 설계 |
| 모델링 | 베이스라인(선형회귀) → 앙상블 비교 → 교차검증 → 체계적 튜닝까지 단계적으로 확장 |
| 결과 해석 | 변수 중요도의 이상 신호를 그냥 보고하지 않고 ablation 실험으로 원인을 검증 |
| 재현성/문서화 | 번호가 매겨진 스크립트, 고정된 random_state, 실행 로그 기반의 문서화 |
| CLI 도구 활용 | 셸에서 스크립트 실행·차트 렌더링 확인·색상 접근성 검증 스크립트 실행을 반복하며 결과를 눈으로 검증 |
